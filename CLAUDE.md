# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with
code in this repository.

## Project Overview

Reproducible setup for Seeed Studio reTerminal (CM4108032: 8GB RAM, 32GB
eMMC, WiFi) kiosk devices: a generic image built on CI (`build-image.py`),
customized per-device at flash time (`flash.py <hostname>`), running a Home
Assistant dashboard via cage (Wayland compositor) + Chromium on the 5"
720x1280 DSI display rotated to landscape.

## Repository Structure

- **`build-image.py`** — builds the generic `reterminal-base.img.xz` (CI or
  local; chroot package install, Seeed driver build, kiosk file deployment).
- **`flash.py <hostname>`** — injects per-device config (hostname, WiFi PSK,
  SSH keys, dashboard URL) and flashes via rpiboot.
- **`kiosk/`** — files deployed to devices (systemd units, launcher
  template, backlight/power-button daemons, hide-cursor extension).
- **`tools/`** — debug/test scripts (touch, i2c, dwc2, backlight test
  servers); never deployed.
- **`docs/`** — `build.md` (build/flash) and `kiosk-setup.md` (hardware
  details, architecture, fixes applied — the authoritative reference).

## Key Hardware Details

- **Display**: 720x1280 native, rotated 270° for landscape (effective 1280x720)
- **Touch**: Goodix I2C at 0x45 via Seeed `mipi_dsi` DKMS driver. **Must use
  separate I2C transactions** (not combined/repeated START). The driver's
  `x_y_rotate()` is patched out at build time (cage handles rotation).
- **Light sensor**: LTR-303ALS at `iio:device0`
  (`/sys/bus/iio/devices/iio:device0/in_illuminance_input`)
- **Backlight**: `/sys/class/backlight/1-0045/brightness` (0-255)
- **Buttons**: 4x GPIO keys (keycodes 30-33 = A/S/D/F) + power (142 =
  KEY_SLEEP). Event device number varies between boots — always discover via
  `/sys/class/input/event*/device/name` matching `gpio_keys`.
- **USB gadget mode**: does NOT work on this hardware (board design
  limitation). Do not attempt.
- **Kernel**: stay on 6.12.x — the Seeed DKMS modules (`bq24179_charger`,
  `ltr30x`) do not build against 6.18+ (kernel removed
  `power_supply_config.of_node`). See docs/kiosk-setup.md.

## Development Patterns

- Deployed scripts are standalone Python (stdlib only) — they run with the
  device's `python3`.
- Test servers (`tools/`) are self-contained HTTP servers with embedded HTML
  that auto-detect hardware paths at startup.
- GPIO/input discovery always globs `/sys/class/input/event*/device/name` —
  never hardcode event numbers.
- Input events are read with `struct` format `"llHHi"`; daemons use
  `select()` for non-blocking I/O — no threads, no external dependencies.

## Deployed-Fleet Note

On devices under fleet management, `/usr/local/bin/kiosk-browser` is
regenerated by the owner's (private) ansible repo — the flash-time URL
injection applies only until first converge. Site-specific configuration
(hostnames, URLs, tokens) deliberately lives there, not here: this repo is
public and generic.

`kiosk/mqtt-sensors` is **deprecated** — superseded by
[mithro/sensors2mqtt](https://github.com/mithro/sensors2mqtt) on managed
devices.
